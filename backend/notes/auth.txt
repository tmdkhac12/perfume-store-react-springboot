- In Spring Security, authentication uses UserDetails(I), it doesn't know about your database
- Spring calls UserDetailsService(I) when it needs to authenticate someone
- GrantedAuthority represents a permission or role in Spring Security, it is used by @PreAuthorize,
.hasRole(), .hasAuthority()
- Spring Security expects a string role for standard processing

- Auth module (Login, register) => Who are you?
- Security/Authorization module => Can you do this action?

- JWT contains 3 parts: header.payload.signature
- How to create a JWT token?
    When a user logs in successfully to the system, the server creates a header, payload and encodes
    them by Base64URL algorithm, after that the server hashes encoded header and payload with the SECRET_KEY
    to create a signature (using HS256 algorithm) and returns "encoded_header.encoded_payload.signature" to
    the user
- How to verify the token?
    When the token reaches the server, the server gets token's header and payload and
    hashes them with the SECRET_KEY again to get a signature, after that it compares the signature to
    the token's signature for checking validation
- SECRET can be string, or base64, but it should be base64 because a string can contain UTF-8 chars
and that can cause exception when you convert the SECRET to bytes[]. Moreover, SECRET must be >= 32 bytes
for HS256 and >= 64 bytes for HS512
- In Spring Security, SECRET must be byte[], so you must decode or .getBytes() the SECRET
- .hmacShaKeyFor() choose the algorithm automatically for you base on the SECRET_KEY (256 for 32 bytes
and 512 for 64 bytes) and wrap the bytes[] inside SecretKey
- .parseSignedClaims() is the method to verify a token
