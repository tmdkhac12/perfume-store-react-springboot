- JPA is a set of rules, it defines all the annotations (@Entity, @Table, @Column, ...)
- Hibernate is an implementation of JPA, it is the engine that executes all the queries and supplies ORM

- Hibernate doesn't need getters and setters for reading database, it bases on the entity's fields to reflect directly to the table's fields, Jackson is the thing relies on public getters and setters from entity to return a response to the user
- Hibernate and JPA entity require a no-args constructor to work
- Hibernate can map Java properties camelCase to database columns snake_case

- @GeneratedValue strategy defines how the id attribute is created, if you don't specify, it will be set AUTO by default, that means Hibernate will choose it base on your DB_URL
- @Transactional ensures that the whole method must success before returning value or everything is rolled back

- Optional (Java 8+) is a wrapper class represents a value that may or may not exist instead of returning null
- .orElse means ifPresent return .get() if not return ...

- JPA works with Object References to manage lazy loading, some features... , not raw ids, so the correct approach is address.setUser(user), not address.setUserId(userId)
- @OneToMany means one row in this class maps with many rows in the attribute
- @OneToMany(mappedBy = "user") determine the datatype's attribute (for inverse side - the table doesn't have a FK)
- @EntityGraph is used to override the relationship with fetch type LAZY to EAGER fetch type, and it helps avoid N query when you load various entity (findAll Perfume is a query, and if the mapper accesses perfume.getSampleImages(), Hibernate will query N times to get images per perfume)
- @ManyToOne is EAGER by default and @OneToMany is LAZY
- @ManyToOne will join instantly, @OneToMany will attach to a new query
- @BatchSize(size = 20) determines the size Hibernate uses to query per time. When you find all Perfume by limit 30, Hibernate will execute 1 query to get 20 SampleImage and 1 query to get 10 SampleImage, using total 3 queries instead of 31 queries, it's a solution for N + 1 query and MultipleBagFetchException

- Specification is a interface helping you build a SQL with optional parameters flexibly, we need Specification to avoid method naming too long such as 'findAllByGenderAndPriceBetweenAndBrand(...)' with Specification, you can treat filter conditions as a puzzle piece and attach them to the query or not
